# ADR-0001: Varbase 11 и принцип «platform first, custom last»

- Статус: Accepted
- Дата: 2026-08-18
- Решение принято для: E+E Master

## Контекст

E+E Master нужен новый корпоративный и экспертный сайт на Drupal. До начала
продуктовой разработки необходимо выбрать стартовую платформу и ограничить
преждевременное создание custom-кода.

Varbase 11 предоставляет recipe-first baseline поверх Drupal 11: Canvas,
редакторские, media, workflow, search, SEO, security, performance и другие
возможности уже собраны в поддерживаемую композицию.

На дату решения Varbase 11.0.0-rc1 является release candidate, поэтому выбор
стартовой платформы не означает автоматического одобрения текущей версии для
production.

## Решение

1. Использовать Varbase 11 как стартовую платформу E+E Master.
2. Следовать принципу **platform first, custom last**.
3. Проверять требования в следующем порядке:
   - Varbase штатно;
   - Drupal core;
   - contrib, уже входящий в baseline;
   - дополнительный зрелый contrib;
   - разумная корректировка требования;
   - custom-код только при доказанном ограничении предыдущих вариантов.
4. Документировать существенные архитектурные решения отдельными ADR.
5. Использовать full-установку только как исследовательский стенд. Production
   recipe composition будет определена отдельным решением после capability map.

## Последствия

Положительные:

- быстрее проверяются требования без преждевременной разработки;
- сохраняются стандартные пути обновления Drupal/Varbase;
- решения становятся проверяемыми и воспроизводимыми.

Риски:

- Varbase 11 пока release candidate;
- full baseline очень широк и содержит pre-release contrib-пакеты и патчи;
- требования могут потребовать адаптации к естественной модели платформы;
- production readiness требует отдельной проверки обновлений, безопасности,
  производительности и совместимости с Beget.

## Альтернативы

- Drupal core / Drupal CMS без Varbase — отклонено для стартового исследования,
  так как не соответствует выбранной основе проекта.
- Немедленная custom-разработка — отклонено как создающая неподтверждённые
  затраты на сопровождение.
- Считать full-набор production baseline — не принято; решение отложено до
  завершения исследования.
